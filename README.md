## Идея

Существуют большие базы паролей, попавших в утечки (миллионы и миллиарды записей). При регистрации или смене пароля полезно проверить, не встречался ли он в таких базах. Хранить весь список и искать в нём при каждой проверке неудобно: он занимает много места, а проверка должна быть быстрой.

Bloom filter хранит информацию о наборе элементов очень компактно и отвечает на вопрос «встречался ли элемент в наборе». Платой за компактность становится возможность ложных срабатываний. Для нашей задачи это допустимо: если хороший пароль случайно попал под срабатывание, пользователю достаточно предложить выбрать другой.

## Как работает Bloom filter

Внутри фильтра лежит битовый массив длиной `m`, изначально заполненный нулями.

- **Добавление.** Для пароля вычисляются `k` позиций в массиве, и эти биты ставятся в 1.
- **Проверка.** Позиции вычисляются снова:
  - хотя бы один бит равен 0 → пароля **точно нет**;
  - все биты равны 1 → пароль **возможно есть**.

Поэтому ложноотрицательных срабатываний не бывает (добавленный пароль всегда найдётся), а ошибиться фильтр может только в одну сторону: сказать «возможно есть» про пароль, которого в базе нет. Это называется ложноположительным срабатыванием (FPR, false positive rate).

### Формулы

| Величина | Формула |
|---|---|
| Размер битового массива | `m = -n · ln(p) / (ln 2)²` |
| Оптимальное число хешей | `k = (m / n) · ln 2` |
| Теоретический FPR | `p ≈ (1 − e^(−k·n/m))^k` |

Здесь `n` — число элементов, `p` — желаемый FPR, `m` — число бит, `k` — число хеш-функций.

### Double hashing

Вместо `k` отдельных хеш-функций мы один раз считаем SHA-256 и берём из него два 64-битных числа `h1` и `h2`. Позиции вычисляются как:

```
position_i = (h1 + i · h2) mod m,   i = 0 … k−1
```

Число `h2` делается нечётным, чтобы шаги не вырождались. Это даёт `k` разных позиций за одно вычисление хеша.

## Быстрый старт

Нужен Python 3.10 или новее. Внешние библиотеки для основного модуля не требуются.

### 1. Клонировать репозиторий

```bash
git clone https://github.com/<ваш-аккаунт>/<название-репозитория>.git
cd <название-репозитория>
```

### 2. Запустить тесты

```bash
python test_bloom_filter.py
```

Ожидаемый результат:

```
OK test_added_found
OK test_unknown_mostly_not_found
OK test_no_false_negatives
OK test_save_load
OK test_params_formulas
```

### 3. Получить данные

Скачайте `rockyou.txt.gz`, распакуйте его в `rockyou.txt` (подробнее в разделе [Данные](#данные)).

### 4. Построить фильтр

```bash
python build_rockyou.py rockyou.txt 0.01 rockyou_1pct.bloom
```

Параметры: путь к списку паролей, желаемый FPR, имя выходного файла. Для остальных вариантов точности:

```bash
python build_rockyou.py rockyou.txt 0.001  rockyou_01pct.bloom
python build_rockyou.py rockyou.txt 0.0001 rockyou_001pct.bloom
```

Скрипт держит все уникальные пароли в памяти (для RockYou это около 1,5–2 ГБ), построение занимает 2–4 минуты.

### 5. Проверить готовый фильтр

Откройте `check.py`, укажите в `FILTER_FILE` имя вашего файла и запустите:

```bash
python check.py
```

Пример вывода:

```
123456 → возможно есть
password → возможно есть
iloveyou → возможно есть
qX7#mP9$zL2vNw8 → точно нет
```

## Использование класса BloomFilter

```python
from bloom_filter import BloomFilter

# создать фильтр на 1 000 000 элементов с FPR 1%
bf = BloomFilter(1_000_000, 0.01)

bf.add("password123")
print(bf.contains("password123"))   # True
print("unknown_pass" in bf)         # почти наверняка False

bf.save("my.bloom")
bf2 = BloomFilter.load("my.bloom")
```

| Метод | Описание |
|---|---|
| `BloomFilter(n, p, k=None, m=None)` | Создать фильтр. `m` и `k` считаются по формулам, но их можно задать вручную (нужно для экспериментов) |
| `add(item)` | Добавить элемент |
| `contains(item)` / `item in bf` | Проверить элемент |
| `save(path)` / `BloomFilter.load(path)` | Сохранить фильтр в файл и загрузить обратно |
| `fill_ratio()` | Доля занятых битов |
| `theoretical_fpr(n=None)` | Теоретический FPR для текущего (или заданного) числа элементов |
| `size_bytes()` | Размер битового массива в байтах |

Формат файла `.bloom`: 4 байта с длиной заголовка, JSON-заголовок (`n`, `p`, `m`, `k`, `count`), затем сам битовый массив.

## Практическая схема: Bloom filter + k-anonymity

Локальный Bloom filter снимает с сервера большую часть проверок, а для оставшихся используется k-anonymity, как в Pwned Passwords (Have I Been Pwned).

```
Пароль
   ↓
Bloom filter (локально)
   ↓
точно нет ─────→ готово, сетевого запроса не было
   │
   ↓
возможно есть
   ↓
клиент считает SHA-1 пароля, отправляет серверу только первые 5 hex-символов
   ↓
сервер возвращает все суффиксы хешей с этим префиксом
   ↓
клиент сам ищет свой суффикс и принимает окончательное решение
```

Что это даёт:

- пароль и полный хеш серверу не передаются, сервер видит только 20-битный префикс;
- Bloom filter не даёт ложноотрицательных срабатываний, поэтому «точно нет» можно принимать без проверки;
- ложные срабатывания фильтра исправляет сервер, итоговый вердикт всегда точный;
- чистые пароли (а их большинство) проверяются без сетевого запроса.

Важная оговорка: локально закрываются только пароли, которых нет в базе. Утёкший пароль фильтр всегда пропускает дальше («возможно есть»), и подтверждает его сервер. Поэтому доля проверок без сети не больше `1 − q`, где `q` — доля утёкших паролей среди проверяемых, и с учётом ложных срабатываний равна примерно `(1 − q)(1 − FPR)`.
